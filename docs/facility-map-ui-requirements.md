# UniPark 施設検索 UI要件書

## 0. デザインアプリへ渡す依頼文

UniParkの「施設を地図から探す画面」と「施設詳細画面」をデザインしてください。

UniParkは、障がいのある人と同行者が、外出前や外出中に必要な情報を確認するためのサービスです。現在は駐車場と施設を検索できますが、この2つだけを扱う専用アプリではありません。将来は、トイレ、移動経路、休憩場所、支援サービスなども追加します。そのため、駐車場と施設はサービス全体の中の「検索対象」として扱ってください。

デザインは、一般的な地図検索サービスや公共交通・自治体サービスのように、落ち着いていて実用的なものにしてください。生成AIのデモ画面に見える、大きすぎる角丸、全面的なカード化、紫や青のグラデーション、過剰な影、意味のない装飾アイコン、短い説明文を大量のバッジにする表現は避けてください。

地図を画面の主役にし、PCでは左に検索・一覧、右に地図を配置します。スマートフォンでは地図とボトムシート型の一覧を基本とします。一覧と地図は連動させ、どちらからでも施設を選べるようにします。

割引の有無だけでなく、車いす対応、補助犬、字幕、音声案内、オストメイト対応などの設備・支援情報を同じ重要度で確認できるようにしてください。「割引なし」と「割引未確認」、「設備なし」と「設備未確認」は、誤解のない別の状態として表示してください。

この文書にある画面状態、項目、アクセシビリティ要件を満たしたPC版・スマートフォン版のデザインと、再利用可能なコンポーネント仕様を作成してください。

## 0.1 デザインの方向性

目指す印象：

- 実用品として信頼できる
- 静かで読みやすい
- 初めてでも操作を推測できる
- 障がい者向けであることを過度に特別扱いせず、必要な情報へ早く到達できる
- データが増えても崩れない

参考にするUIの考え方：

- Google MapsやYahoo!マップのような、地図と検索結果が連動する基本構造
- 自治体や公共交通サイトのような、状態と条件を文章で正確に伝える情報設計
- 不動産検索サイトのような、複数条件を段階的に絞り込める操作

参考サイトの外観をそのまま複製する必要はない。共通している「予測しやすい操作」「過度に飾らない情報表示」「地図を邪魔しない検索UI」を取り入れる。

### 避ける視覚表現

- ページ全体を薄いグレーの背景にし、すべてを白い角丸カードへ入れる
- 16px以上の大きな角丸をほぼ全要素へ適用する
- 青紫、ピンク、シアンなどのグラデーションをブランド表現として使う
- ガラス風の半透明、強いぼかし、発光、浮遊するパネル
- すべての見出しへアイコンを置く
- 情報を細かく分割しすぎたチップやバッジの列
- 大きなキャッチコピーや説明文で、検索開始までの距離を長くする
- 「駐車場」「施設」をサービス全体の最上位機能として大きく見せる

### 推奨する視覚表現

- 白またはごく淡い無彩色を基調に、文字と罫線で階層を作る
- 角丸は入力欄・ボタンで4〜8px程度を基本とし、用途ごとに一貫させる
- 影は地図上の浮遊パネルなど、前後関係を示す必要がある場所だけに使う
- ブランド色は1色を主軸にし、選択、リンク、重要な状態へ限定する
- 本文は黒に近い無彩色、補足は十分なコントラストを持つグレーにする
- 状態は色だけでなく、短いラベルと説明文を併用する
- 区切り線、余白、文字の太さで情報を整理する

## 0.2 今回デザインしないもの

- データ収集・管理画面
- 調査の自動化画面
- ログイン、会員登録、課金
- お気に入り、口コミ、投稿
- 施設予約や決済
- 休館・営業中をリアルタイム表示する機能

ただし、将来これらを追加できるように、画面構造を特定機能へ固定しすぎない。

## 1. この画面の位置づけ

UniParkは、障がいのある方や介助者のお出かけ判断を支援するサービスである。

駐車場検索と施設検索はサービス全体の一機能であり、ブランド全体を「駐車場と施設だけのアプリ」に見せない。今後、トイレ、移動経路、支援サービスなど別の検索対象が増えても拡張できる構造にする。

今回デザインする対象は、以下の2画面。

1. 施設を地図から探す画面
2. 施設の詳細情報を見る画面

## 2. 利用者と利用場面

主な利用者：

- 障がいのある本人
- 家族、介助者、同行者
- 外出先を事前に調べる人
- 現地周辺で利用可能な施設を探す人

主な利用場面：

- 現在地や目的地周辺で利用可能な施設を探す
- 障がい者割引がある施設だけを探す
- 車いす、補助犬、字幕、音声ガイドなどの対応状況を調べる
- 利用条件、対象手帳、介助者の扱いを確認する
- 公式サイトで最新情報を確認する

## 3. デザイン原則

- 地図を主役にする
- 情報量が多いため、装飾より可読性と検索性を優先する
- 一般的な地図検索サービスとして自然に見えること
- 大きな角丸カード、グラデーション、過剰なバッジ、装飾アイコンを多用しない
- 色だけで状態を伝えない。色と文字を併用する
- 「割引なし」と「割引未確認」を明確に区別する
- 「設備なし」と「設備未確認」を明確に区別する
- 無料施設も除外せず、「入場無料・利用無料」として表示する
- 休館情報は主要な検索・表示条件にしない
- スマートフォンで片手操作しやすいこと
- 将来、検索対象が増えても全体ナビゲーションを作り直さずに済むこと

## 4. サービス共通ヘッダー

必要な要素：

- UniParkロゴまたはワードマーク
- 「マップから探す」への導線
- 「UniParkについて」への導線
- 将来の追加機能を配置できる余白またはメニュー

避ける構成：

- ヘッダー中央に「駐車場」「施設」だけを大きなタブとして並べる
- 駐車場と施設がサービスの全機能であるように見せる

駐車場と施設の切り替えは、全体ナビゲーションではなく「マップから探す」画面内の検索対象切り替えとして扱う。

## 5. 施設マップ画面

### 5.1 PCレイアウト

- 左側：検索条件と検索結果一覧
- 右側：地図
- 地図は画面内で最大の面積を確保する
- 左側の一覧は独立して縦スクロールできる
- ヘッダーを除き、基本的に1画面の高さに収める

左カラムの目安は380〜440px。固定値に限定せず、デザイン上適切な幅を選べる。

### 5.2 スマートフォンレイアウト

- 最初に地図を表示する
- 地図の下に検索条件と検索結果一覧を表示する
- または地図上に展開可能なボトムシートとして一覧を配置する
- 地図と一覧のどちらを見ているか分からなくならないこと
- マーカー選択後の施設情報が画面外へ隠れないこと

### 5.3 必要な検索条件

- フリーワード検索
  - 施設名
  - 住所
  - 割引内容
  - バリアフリー設備名
  - 支援内容
- 市区町村
- 施設種別
- 情報の種類
  - すべて
  - 障がい者割引あり
  - バリアフリー設備・支援情報あり
  - 割引未確認

追加候補として検討できる条件：

- 本人無料
- 介助者・同行者への割引あり
- 居住地制限なし
- ミライロID対応
- 車いす対応
- 補助犬同伴
- 字幕・聴覚支援
- 音声・視覚支援
- オストメイト対応
- 障がい者用駐車場

### 5.4 検索結果一覧に必要な情報

必須：

- 施設名
- 市区町村
- 施設種別
- 割引状態
- 割引内容の要約
- 住所

情報がある場合に表示：

- 主なバリアフリー設備または支援内容
- 居住地制限
- 介助者・同行者条件

一覧では詳細情報をすべて表示せず、比較と選択に必要な内容へ絞る。

### 5.5 地図マーカー

- 検索条件に一致する施設だけを表示する
- 割引ありと、それ以外を視覚的に区別できる
- 選択中のマーカーが明確に分かる
- マーカーの意味を示す凡例がある
- マーカー同士が密集した場合のクラスタリングを将来的に考慮する
- 色だけに依存せず、必要に応じて形やアイコンも組み合わせる

### 5.6 施設選択時

一覧またはマーカーを選択すると：

- 対応するマーカーと一覧項目が選択状態になる
- 地図が施設位置へ移動する
- 地図上に簡易情報を表示する
- 施設詳細画面へのボタンまたはリンクを表示する

簡易情報に必要な項目：

- 施設名
- 市区町村、施設種別
- 割引内容の要約、または割引未確認
- 詳細への導線

## 6. 施設詳細画面

### 6.1 ページ先頭

- 施設一覧へ戻る導線
- 施設名
- 市区町村
- 施設種別
- 住所
- 情報状態
  - 障がい者割引あり
  - 割引なし
  - 割引未確認
  - 入場無料・利用無料
  - バリアフリー設備・支援情報あり

### 6.2 割引・料金

表示可能な項目：

- 通常料金
- 障がい者向け割引内容
- 割引対象サービス
- 対象となる手帳
- 対象となる受給者証や証明書
- 等級や区分の条件
- 居住地条件
- 介助者・同行者の条件
- 利用時に必要な提示物や手続き

割引を確認できない場合は、空欄にせず「公式情報から障がい者割引を確認できていません」と表示する。

### 6.3 バリアフリー設備・支援

表示対象：

- 車いすでの利用可否
- 車いす席、観覧スペース
- 車いす対応経路、入口、スロープ
- 車いす貸出
- エレベーター
- 車いす対応トイレ
- オストメイト対応
- 障がい者用駐車場
- 補助犬同伴
- 筆談
- 聴覚支援
- 字幕、字幕端末
- 音声ガイド
- 点字、触知案内
- 視覚支援
- 感覚特性への配慮
- その他の人的支援

各項目には次の状態がある：

- 利用可能
- 条件付き・事前確認が必要
- 利用不可・設備なし
- 未確認

### 6.4 利用前の確認

- 電話番号
- 予約や事前連絡の必要性
- 利用上の注意
- 備考

### 6.5 公式情報源

- すべての根拠URLを表示する
- 外部サイトへ移動することが分かる表現にする
- 情報確認日を表示する
- 最新情報は公式サイトまたは施設へ確認する旨を表示する

## 7. 表示状態の定義

### 割引状態

| データ値 | 表示上の意味 |
|---|---|
| `available` | 現在有効な障がい者割引を公式確認済み |
| `historical` | 過去の割引情報として確認済み |
| `none` | 公式に割引なしと確認済み |
| `not_applicable` | 通常料金自体が無料など、障がい者割引の適用対象外 |
| `unverified` | 公式情報から割引の有無を確認できていない |

### バリアフリー確認状態

| データ値 | 表示上の意味 |
|---|---|
| `verified` | 公式情報で設備・支援内容を確認済み |
| `partial` | 一部の設備・支援内容のみ確認済み |
| `unverified` | 公式情報で確認できていない |

### 個別設備の状態

| データ値 | 表示上の意味 |
|---|---|
| `available` | 利用可能 |
| `conditional` | 条件付き、予約、事前連絡などが必要 |
| `unavailable` | 利用不可、または設備なし |

- 美術館・ギャラリー
- 劇場・ホール
- 映画館
- プール
- スポーツ施設

## 9. データ更新への対応

- 施設データは継続的に追加される
- 現在は千代田区と中央区の79施設
- 市区町村は今後、東京都全域へ増える
- 市区町村や施設種別はデータから自動生成する
- デザイン上、件数が数千件になっても破綻しないこと
- 緯度・経度が未登録の施設が存在する可能性を考慮する
- 地図へ表示できない施設も一覧から消さない

## 10. アクセシビリティ要件

- WCAG 2.2 AA相当を目標とする
- 本文文字サイズは原則14px以上
- 操作対象は最低44×44pxを目安にする
- キーボードのみで検索、選択、詳細移動ができる
- フォーカス位置が目視できる
- コントラストを確保する
- マーカーに施設名のアクセシブルネームを付ける
- アイコンだけのボタンにはラベルを付ける
- 地図が操作できなくても一覧から同じ情報へ到達できる
- 動きが苦手な利用者へ配慮し、不要なアニメーションを避ける

## 11. 必要な画面状態

デザインに含める状態：

- 初期表示
- 検索結果あり
- 検索結果0件
- マーカー／施設選択中
- 割引あり
- 割引なし
- 割引未確認
- 設備情報のみあり
- 条件付き設備あり
- 地図読み込み中
- 地図を利用できない場合
- データ読み込み失敗
- スマートフォン表示
- PC表示

## 12. 受け入れ条件

- 画面を開いた直後に地図と施設の位置が分かる
- 地域、施設種別、情報種別、キーワードで絞り込める
- 絞り込み結果と地図マーカーが一致する
- 一覧と地図のどちらからでも施設を選べる
- 選択した施設の詳細画面へ移動できる
- 割引なしと割引未確認を誤認しない
- 料金、対象手帳、介助者条件、バリアフリー設備を確認できる
- 公式情報源へ移動できる
- スマートフォンとPCの両方で主要操作が可能
- 駐車場と施設が、UniPark全体の一部機能として見える
- 将来の検索対象追加を妨げない

## 16. デザインデータの例

デザインでは、単純な「割引あり」だけでなく、次のような差のある施設を混在させる。

- 本人無料、介助者1名無料の美術館
- 一部サービスのみ割引になる複合施設
- 区内在住者だけ無料になるプール
- 入場自体が無料で、車いす対応などの設備情報がある施設
- 割引を公式確認できないが、補助犬や車いす対応を確認できる施設
- 割引も設備も未確認の施設
- 長い条件説明、複数の対象手帳、事前連絡が必要な施設
- 緯度・経度がなく、一覧だけに表示される施設

短いダミー文だけで作ると実データ投入時に崩れるため、一覧の説明は2〜3行、詳細の条件文は数行になるケースも作る。

## 17. デザイン完了時の引き渡し条件

- PC幅とスマートフォン幅の主要画面が揃っている
